# AI画面生成 機能設計

「AIで画面を生成」の作り込みに関する設計。**本ドキュメントは設計のみ**で、
実装は含まない。`docs/SPECIFICATION.md` の M3（Claude Code連携）に属する。

対象の要件:

1. 「AIで画面を生成」押下でポップアップ表示（実装済み）
2. 内容を入れて「生成」を押すと、Claude Code とのやりとりが見える
3. Claude Code が「生成する画面の案（数・内容）」を提示し、ユーザーが確認して
   必要に応じて指示できる
4. 指示が確定してから画面を作り始める
5. 生成時に適用したいスキル／デザインシステムをプロジェクト情報で設定できる
6. 画面は順次生成され、キャンバスにサムネイルが出る
   - PC／スマホでサムネイルの縦横比を変える（縦長画面はそのままではなく
     一定サイズで上部クロップでよい）

---

## 1. 全体フロー（状態機械）

生成は「入力 → 構成案 → レビュー → 生成 → 完了」の段階を持つ1つの**生成ラン**。

```
 INPUT ──生成──▶ PROPOSING ──案を提示──▶ REVIEW ─┬─指示して再検討──▶ PROPOSING
 (入力)          (構成検討中)             (確認)  │      (案を作り直す)
                                                 ├─この内容で作成──▶ GENERATING ──▶ DONE
                                                 └─キャンセル──▶ (破棄)             (完了)
                          いずれの段でも ──中断/エラー──▶ CANCELED / ERROR
```

- **INPUT**: 指示テキスト＋ファイル添付＋対象フォームファクタの既定（実装済みの
  ポップアップを拡張）。
- **PROPOSING**: Claude Code がプロジェクト前提情報・適用スキル・デザインシステム・
  入力をもとに「画面構成案」を考える。やりとり（思考・メッセージ・ファイル操作）を
  ストリーミング表示。
- **REVIEW**: 構成案（画面数と各画面の内容）を一覧表示。ユーザーは内容を確認し、
  - 個別に編集（名前・グループ・説明・デバイス・削除・追加）
  - もしくは自由文で指示（「決済画面は不要」「管理者画面も足して」等）→ 再検討
  - 問題なければ「この内容で作成」
- **GENERATING**: 確定した画面を**1画面ずつ順次**生成。完了ごとにサムネイルを
  キャプチャしキャンバスへ反映。進捗を表示。途中中断可。
- **DONE / ERROR / CANCELED**: 結果サマリ。

「指示を受け取ってから画面を作り始める」要件は、REVIEW→GENERATING の明示的な
承認（この内容で作成）で担保する。承認前に `screens` 実体やコードは作らない。

## 2. 画面設計

### 2.1 配置方針 — キャンバス右側のドロワー

構成案の確認・やりとり・進捗は領域が必要で、かつ「生成されるサムネイルが
キャンバスに出る」様子を**同時に**見せたい。そこで生成UIは
**キャンバス右側にドッキングするドロワー**とする。左にキャンバス（サムネイルが
順次増える）、右にやりとり／レビュー／進捗。

入力ポップアップ（実装済み）の「生成」押下で、ポップアップを閉じてドロワーを開く。

```
┌─ プロジェクトキャンバス ───────────────┬─ AI生成ドロワー ───────────┐
│  [AIで画面を生成] [既存の画面を取り込み] │  ● 構成を検討中 / レビュー / 生成中 │
│                                        │                             │
│  ▼ 認証                                │  ┌─ やりとり（ストリーム）──┐ │
│  ┌────┐ ┌────┐ (生成中…)              │  │ AI: 企画書を読み込みました │ │
│  │thumb│ │skel│                       │  │ AI: 5画面を提案します…    │ │
│  └────┘ └────┘                        │  │ [Edit] app/screens/...    │ │
│  ▼ メイン機能                          │  └──────────────────────────┘ │
│  ┌────┐ ┌────┐ ┌────┐                 │  （フェーズ別の操作パネル）  │
│  └────┘ └────┘ └────┘                 │  [指示...] [この内容で作成]  │
└────────────────────────────────────────┴─────────────────────────────┘
```

ドロワーは生成ラン単位で、`/projects/[id]?gen=<runId>` のように状態を持つ。
リロードしても進行中のランに復帰できるよう、ランIDはURLまたはサーバー状態から復元する。

### 2.2 PROPOSING（構成検討中）

```
┌─ AI生成 ─────────────────[×]┐
│ ● 構成を検討中…              │
│ ┌─ やりとり ───────────────┐ │
│ │ あなた: ECサイトの管理画面 │ │
│ │ AI: 企画書を確認します     │ │
│ │ 〔Read〕inputs/plan.pdf    │ │
│ │ AI: 画面構成を検討中…      │ │  ← ストリーミング
│ └───────────────────────────┘ │
│                    [中断]      │
└──────────────────────────────┘
```

- Claude のテキスト・ツール使用（Read/Write/Edit 等）を種別付きで時系列表示。
- ツール使用は「どのファイルを読んだ/書いたか」を1行サマリで（詳細は折りたたみ）。

### 2.3 REVIEW（構成案の確認・指示）

```
┌─ AI生成 ───────────────────────[×]┐
│ 構成案（6画面）  対象: PC / スマホ   │
│ ┌─ 認証 ──────────────────────────┐ │
│ │ ☑ ログイン      [PC▼] [✎][🗑]    │ │
│ │ ☑ パスワード再設定 [PC▼][✎][🗑]  │ │
│ └──────────────────────────────────┘ │
│ ┌─ 管理 ──────────────────────────┐ │
│ │ ☑ 商品一覧      [PC▼] [✎][🗑]    │ │
│ │ ☑ 商品詳細      [PC▼] [✎][🗑]    │ │
│ │ ☐ 売上ダッシュ  [PC▼] [✎][🗑]    │ │ ← チェックを外すと生成対象から除外
│ └──────────────────────────────────┘ │
│ [＋画面を追加] [＋グループを追加]      │
│                                      │
│ ┌─ 追加で指示（任意）──────────────┐ │
│ │ 例: モバイル版も用意して           │ │
│ └──────────────────────────────────┘ │
│ [指示して再検討]  [この内容で作成]    │
│                         [キャンセル]  │
└──────────────────────────────────────┘
```

各案の項目（編集可能）:

- 画面名 / グループ / 説明（役割・主要コンポーネントの想定）
- デバイス（PC / スマホ）← サムネイル比率と生成時のビューポートに反映
- 生成対象に含めるか（チェック）

操作:

- **指示して再検討**: 自由文＋現在の編集内容を Claude に渡し、案を作り直す（PROPOSING へ）。
- **この内容で作成**: チェックされた案を確定し GENERATING へ。確定時点で初めて
  `screens` に行を作成（status=`proposed`→`generating`）。

> 構成案の「説明」と「主要コンポーネント」は、後段の各画面生成プロンプトと、
> 本開発で使う `screen_components` の初期値に流用する。

### 2.4 GENERATING（順次生成・進捗）

```
┌─ AI生成 ───────────────────[×]┐
│ 生成中  3 / 6 完了             │
│ ☑ ログイン        生成済み     │
│ ☑ パスワード再設定 生成済み     │
│ ◐ 商品一覧        生成中…      │  ← 現在の画面はキャンバスでスケルトン表示
│ ・商品詳細        待機         │
│ ・商品登録        待機         │
│ ・設定            待機         │
│ ┌─ やりとり ───────────────┐   │
│ │ 〔Write〕app/screens/.../  │   │
│ └───────────────────────────┘   │
│                    [中断]        │
└──────────────────────────────────┘
```

- 1画面ずつ Claude Code に作らせ、完了→キャプチャ→キャンバスのサムネ更新、を繰り返す。
- 失敗した画面は status=`error` にして次へ進む（全体は止めない）。後で個別再生成。
- 中断: 進行中ターンを止め、未着手は `proposed` のまま残す。

### 2.5 DONE / ERROR

- 完了サマリ（成功 N / 失敗 M）。失敗があれば該当画面に再生成導線。
- 重大エラー（Claude Code 未連携・認証切れ等）はアプリ設定への導線を出す。

## 3. キャンバスのサムネイル（デバイス別アスペクト比）

### 3.1 デバイス区分

`screens` に `device`（`desktop` | `mobile`）を持たせる。生成時のレンダリング
ビューポートと、カードのアスペクト比の両方を決める。

| device | 生成ビューポート（幅） | キャプチャのクロップ | カードのアスペクト比 |
|---|---|---|---|
| desktop | 1440 | 上部 1440×900 を切り出し | `16 / 10`（横長） |
| mobile | 390 | 上部 390×694 を切り出し | `9 / 16`（縦長） |

> 「縦に長い画面をそのまま表示しない」要件は、**フルページではなく上部固定高で
> クロップ**することで満たす。スマホ画面が縦に長くてもサムネは上部だけを一定比率で表示。
> 実装はキャプチャ時に `clip`（領域指定スクショ）で固定高を切り出す（M2）。

### 3.2 グリッド表示

- カードは `device` でアスペクト比が変わる（desktop=横長、mobile=縦長）。
- グリッドは `items-start` で高さの違いを許容。各カードに `PC` / `スマホ` の
  小さなバッジを表示。
- 同一グループ内で PC とスマホが混在しうる。混在時の見栄えのため、表示切替
  （全部 / PCのみ / スマホのみ）のフィルタを将来追加可能とする（初期は混在表示）。

### 3.3 デバイスの決まり方

- 入力ポップアップで「対象フォームファクタ」の既定（PC / スマホ / 両方）を選ぶ。
- Claude が構成案で各画面に `device` を割り当て、REVIEW で個別に変更可能。
- 「両方」を選んだ場合、Claude は主要画面について PC版・スマホ版の両方を提案しうる。

## 4. プロジェクト設定の拡張（スキル・デザインシステム）

生成時に Claude Code に適用させる設定をプロジェクト設定ポップアップに追加する。
設定値は `workspace/CLAUDE.md` に書き出し、生成ランの度に常時参照させる。

### 4.1 適用スキル

- AppCanvas は各プロジェクトの `workspace/.claude/skills/` に生成向けスキルを
  同梱する（例: フロントデザイン、React/Next.js ベストプラクティス等）。
- プロジェクト設定で、利用可能なスキル一覧をチェックボックスで選択。
- 選択したスキルは生成プロンプト／CLAUDE.md で明示し、Claude が読み込んで適用する。
- ユーザー追加スキル（独自）も将来的に取り込めるようにする。

```
┌─ プロジェクト設定 ▸ 生成設定 ──────────┐
│ 適用するスキル                          │
│  ☑ フロントデザイン                     │
│  ☑ React/Next.js ベストプラクティス     │
│  ☐ アクセシビリティ監査                 │
└────────────────────────────────────────┘
```

### 4.2 デザインシステム

3通りの与え方を許容し、すべて CLAUDE.md と共有コンポーネントに反映する:

1. **ガイドライン（自由記述）**: 配色・タイポ・余白・トーンなどの方針テキスト。
2. **デザイントークン／参照ファイル添付**: トークン定義や既存のスタイル定義
   （CSS変数・Tailwind設定など）。`workspace/design/` に配置。
3. **共有コンポーネント**: `workspace/components/` に置いた既存コンポーネントを
   「使い回す部品」として参照させる。

```
┌─ プロジェクト設定 ▸ デザインシステム ──┐
│ ガイドライン                            │
│ ┌──────────────────────────────────┐  │
│ │ 配色: 角丸最小、アクセントは青     │  │
│ │ タイポ: 見出し太字、本文14px       │  │
│ └──────────────────────────────────┘  │
│ 参照ファイル  [トークンを添付]          │
│  ・design/tokens.css                    │
│ 共有コンポーネント（workspace/components）│
│  ・Button.tsx ・Card.tsx                │
└────────────────────────────────────────┘
```

## 6. API設計（実装時の指針）

| メソッド/パス | 役割 |
|---|---|
| `POST /api/projects/[id]/inputs` | 添付ファイルを `inputs/` へ保存（生成前） |
| `POST /api/projects/[id]/generations` | ランを作成し PROPOSING を開始（→ runId） |
| `GET  /api/projects/[id]/generations/[runId]/stream` | SSE: やりとり＋フェーズ遷移＋構成案更新＋生成進捗 |
| `POST /api/projects/[id]/generations/[runId]/revise` | 自由文指示＋編集済み案を渡して再検討 |
| `POST /api/projects/[id]/generations/[runId]/approve` | 確定案を渡し GENERATING を開始 |
| `POST /api/projects/[id]/generations/[runId]/cancel` | 中断 |
| `GET  /api/projects/[id]/screens/[screenId]/thumbnail` | サムネ配信（M2と共通） |
| `PATCH /api/projects/[id]`（拡張） | skills / design_system / default_device |

SSEイベント種別（例）: `message`（やりとり追記）, `phase`（状態遷移）,
`proposal`（構成案更新）, `screen_status`（画面ごとの生成状態）, `error`, `done`。

## 7. Claude Code連携の仕組み

### 7.1 構成案の受け渡し — proposal.json 方式

Claude Code はファイル編集に強いエージェントなので、構成案は**ファイル経由**でやりとりする。

- 生成プロンプトで「構成案を `.appcanvas/runs/<runId>/proposal.json` に
  指定スキーマで書く」よう指示。
- ターン終了後にオーケストレーターが読み取り、`generation_runs.proposal` に保存して
  REVIEW に渡す。
- 再検討（revise）は同じ Claude Code セッションを `resume` し、指示＋現在の編集内容を
  渡して proposal.json を書き直させる。
- 思考やメッセージは別途ストリームで `generation_messages` に蓄積し画面表示。

（代替案: 構成提案を受け取る専用のカスタムツールを定義する方式。ツール配線が増えるため、
初期は proposal.json 方式を採用。）

### 7.2 順次生成

- `approve` 後、確定案を順に処理。1画面ごとに「`app/screens/<screenId>/page.tsx` を
  作成。Tailwind使用。主要要素に `data-cid` 付与（SPECIFICATION.md の規約）。
  デバイス=スマホなら幅 390 を想定」等の指示を Claude Code に送る。
- 完了→M2のキャプチャ（device に応じたビューポートと上部クロップ）→サムネ反映。
- 1画面=1ターンにすることで進捗が明確になり、失敗の局所化と再生成が容易。

### 7.3 安全境界・モデル

- `cwd` は workspace 固定、許可ツールはファイル操作系（SPECIFICATION.md 6.1）。
- 使用モデルはアプリ設定の選択値（haiku/sonnet/opus）を `query` の `model` に渡す。
  「自動で高額にならない」方針を維持。

## 8. 確定した設計判断

- **生成UIの置き場所** … キャンバス右ドロワー（生成中のサムネが同時に見える）。
- **デバイス区分の粒度** … 画面ごとに `desktop`/`mobile`。`tablet` は当面なし。
- **サムネ比率の具体値** … PC=16:10（上部1440×900）、スマホ=9:16（上部390×694）。
- **構成案の受け渡し** … proposal.json 方式（カスタムツールは後日検討）。
- **スキルの供給元** … workspace に同梱したスキルをプロジェクト設定で選択。
- **混在グリッドの見せ方** … 初期は混在表示＋デバイスバッジ、フィルタは将来。

## 8.1 追加: タブUIと開発コード生成（実装済み）

プロジェクトを3タブ構成にした（ルートグループ `app/projects/[id]/(tabs)/`、共通レイアウトで
ヘッダ＋タブ）。画面詳細はタブ外。

- **キャンバス** … 既存。
- **プレビュー** … 左に画面名（プレビューHTML）一覧、右に `/preview/[id]/[screenId]` の iframe。
  iframe内で別画面に遷移したら左の選択も追従（同一オリジンの location を読む）。
- **開発コード** … 左にファイルツリー、右にコード（閲覧専用）。`/api/projects/[id]/code/tree`・
  `/code/file`（パストラバーサル対策あり、`.appcanvas`/空ディレクトリは除外）。

生成フローの変更:

- **画面生成はHTMLのみ**にした（`.appcanvas/<id>/preview.html` のみ。page.tsx は書かない）。
- **開発コードは別ボタンで生成**（`POST /api/projects/[id]/code-generations`）。プロジェクト全画面の
  プレビューHTML＋コンポーネント情報を元に Next.js コードを workspace に作成。2回目以降は既存コードを
  読み込み差分追加。`generation_runs.kind`（`screens`|`code`）で区別し、ストリーム/中断は既存の
  `/generations/[runId]/stream`・`/cancel` を流用。

## 9. 実装順序

1. **基盤**（本コミット〜）: データモデル追加（projects に skills /
   design_system / default_device、screens に device）、プロジェクト生成設定UI
   （スキル選択・デザインシステム・既定デバイス）、キャンバスのデバイス別サムネ比率。
